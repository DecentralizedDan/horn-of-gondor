# Horn of Gondor — MVP API Contract

## Status

This document defines the API contract between the Raspberry Pi receiver, the Cloudflare service, and the public website. It is the source of truth for MVP implementation and tests.

API version: `v1`

Base path: `/api/v1`

## Design Decisions

- The Pi generates a UUID for each detected transmission before saving it locally.
- Uploads are idempotent. Retrying an upload must not create a duplicate.
- The Pi sends one completed transmission per upload.
- Cloud data is public and read-only.
- Upload and settings endpoints require a secret bearer token.
- All timestamps use RFC 3339 UTC with millisecond precision.
- Durations use integer milliseconds.
- Frequencies use integer hertz.
- Signal levels use dBFS and are relative, not calibrated S-units.
- Public list results are ordered from newest to oldest.
- The browser polls the latest-result endpoint every five seconds.

## Transmission Resource

A transmission has these fields:

- `eventId`: UUID v4 generated by the Pi.
- `startedAt`: RFC 3339 UTC timestamp for the beginning of the detected transmission.
- `durationMs`: Length of the transmission in milliseconds.
- `peakDbfs`: Highest measured signal level during the transmission.
- `averageDbfs`: Mean measured signal level during the transmission.
- `score`: Integer relative-strength score from 0 through 100, calculated by
  the Pi using the configured score range.
- `frequencyHz`: Configured receive frequency in hertz.
- `gainDb`: Configured fixed RTL-SDR gain in decibels.
- `thresholdDbfs`: Configured signal-detection threshold in dBFS.
- `receiverVersion`: Version of the Pi receiver software that produced the measurement.
- `receivedAt`: Server-generated RFC 3339 UTC timestamp. This field appears in responses but is not supplied by the Pi.

Example public resource:

```json
{
  "eventId": "3157bbbf-7208-4873-9c1c-e99965a0d6c4",
  "startedAt": "2026-10-09T00:31:42.127Z",
  "durationMs": 4380,
  "peakDbfs": -31.4,
  "averageDbfs": -39.8,
  "score": 76,
  "frequencyHz": 146550000,
  "gainDb": 28.0,
  "thresholdDbfs": -62.0,
  "receiverVersion": "0.2.0",
  "receivedAt": "2026-10-09T00:31:47.019Z"
}
```

## Validation

The service rejects a transmission unless:

- `eventId` is a valid UUID v4.
- `startedAt` is a valid RFC 3339 UTC timestamp.
- `durationMs` is an integer from 1,000 through 3,600,000.
- `peakDbfs`, `averageDbfs`, and `thresholdDbfs` are finite numbers no greater than `0`.
- `peakDbfs` is greater than or equal to `averageDbfs`.
- `score` is an integer from `0` through `100`.
- `frequencyHz` is an integer from `144000000` through `148000000`.
- `gainDb` is a finite number from `0` through `60`.
- `receiverVersion` is a nonempty string no longer than 50 characters.
- The JSON request body is no larger than 16 KiB.

The receiver calculates average strength from above-threshold samples. Samples
used only to confirm the end-of-transmission grace period are not included.

## Score Calculation

The Pi calculates the score before storing or uploading a transmission. Its
JSON configuration includes `scoreRangeDb`, which defaults to `50`.

For peak and average strength separately:

```text
normalized = clamp(
  (measurementDbfs - thresholdDbfs) / scoreRangeDb,
  0,
  1
)
```

The final score is:

```text
score = round(100 × (0.4 × normalizedPeak + 0.6 × normalizedAverage))
```

The configured threshold represents 0. A measurement at least
`scoreRangeDb` above the threshold represents 100 for that component.
Duration does not affect the score. The receiver rejects a configuration when
`thresholdDbfs + scoreRangeDb` exceeds `0 dBFS`.

## Authentication

The Pi sends its upload secret in the HTTP header:

```text
Authorization: Bearer <secret>
```

The Cloudflare Worker stores the expected value as an encrypted Worker secret. The token must never appear in source control, URLs, logs, public API responses, or website code.

Public `GET` endpoints do not require authentication. Authenticated endpoints do not enable cross-origin browser requests.

## Create a Transmission

`POST /api/v1/transmissions`

Authentication: required.

Request body:

```json
{
  "eventId": "3157bbbf-7208-4873-9c1c-e99965a0d6c4",
  "startedAt": "2026-10-09T00:31:42.127Z",
  "durationMs": 4380,
  "peakDbfs": -31.4,
  "averageDbfs": -39.8,
  "score": 76,
  "frequencyHz": 146550000,
  "gainDb": 28.0,
  "thresholdDbfs": -62.0,
  "receiverVersion": "0.2.0"
}
```

New event response: `201 Created`

```json
{
  "data": {
    "eventId": "3157bbbf-7208-4873-9c1c-e99965a0d6c4",
    "receivedAt": "2026-10-09T00:31:47.019Z",
    "duplicate": false
  }
}
```

An exact retry of an existing event returns `200 OK` with `duplicate` set to `true`.

Reusing an existing `eventId` with different event data returns `409 Conflict` with the error code `event_conflict`.

## Get the Latest Transmission

`GET /api/v1/transmissions/latest`

Authentication: none.

When a result exists, the service returns `200 OK`:

```json
{
  "data": {
    "eventId": "3157bbbf-7208-4873-9c1c-e99965a0d6c4",
    "startedAt": "2026-10-09T00:31:42.127Z",
    "durationMs": 4380,
    "peakDbfs": -31.4,
    "averageDbfs": -39.8,
    "score": 76,
    "frequencyHz": 146550000,
    "gainDb": 28.0,
    "thresholdDbfs": -62.0,
    "receiverVersion": "0.2.0",
    "receivedAt": "2026-10-09T00:31:47.019Z"
  }
}
```

Before the first result, the service returns `200 OK`:

```json
{
  "data": null
}
```

The endpoint supports `ETag` and `If-None-Match`. It may return `304 Not Modified`. Its shared-cache lifetime is five seconds.

## List Transmission History

`GET /api/v1/transmissions`

Authentication: none.

Supported query parameters:

- `limit`: Optional integer. The default is `50`; the maximum is `100`.
- `cursor`: Optional opaque pagination cursor returned by the previous request.
- `since`: Optional RFC 3339 UTC timestamp with millisecond precision. Only
  transmissions beginning at or after this time are returned.

Response: `200 OK`

```json
{
  "data": [
    {
      "eventId": "3157bbbf-7208-4873-9c1c-e99965a0d6c4",
      "startedAt": "2026-10-09T00:31:42.127Z",
      "durationMs": 4380,
      "peakDbfs": -31.4,
      "averageDbfs": -39.8,
      "score": 76,
      "frequencyHz": 146550000,
      "gainDb": 28.0,
      "thresholdDbfs": -62.0,
      "receiverVersion": "0.2.0",
      "receivedAt": "2026-10-09T00:31:47.019Z"
    }
  ],
  "pagination": {
    "nextCursor": null,
    "hasMore": false
  }
}
```

The cursor encodes the last item's `startedAt` and `eventId`, but clients must treat it as opaque. When `since` and `cursor` are combined, the lower time boundary applies to every page.

## Update Retention Settings

`PUT /api/v1/settings`

Authentication: required.

The Pi calls this endpoint at startup. Restarting the receiver after changing
its local configuration keeps cloud retention aligned with the JSON
configuration on the Pi.

Request body:

```json
{
  "retentionDays": 180
}
```

`retentionDays` must be an integer from `1` through `3650`.

Response: `200 OK`

```json
{
  "data": {
    "retentionDays": 180,
    "updatedAt": "2026-10-09T00:30:00.000Z"
  }
}
```

The service uses 180 days until the Pi first updates this setting. A daily Cloudflare Cron Trigger deletes expired cloud records. The Pi independently applies the same configured period to synchronized local records. Unsynchronized records must not be deleted merely because they reached the retention age.

## Error Format

Errors use this JSON structure:

```json
{
  "error": {
    "code": "validation_error",
    "message": "The request contains invalid fields.",
    "details": [
      {
        "field": "durationMs",
        "message": "Must be an integer from 1000 through 3600000."
      }
    ]
  }
}
```

Supported status codes and stable error codes:

- `400 Bad Request`: `invalid_json`, `validation_error`, or `invalid_cursor`
- `401 Unauthorized`: `unauthorized`
- `404 Not Found`: `not_found`
- `405 Method Not Allowed`: `method_not_allowed`
- `409 Conflict`: `event_conflict`
- `413 Content Too Large`: `payload_too_large`
- `503 Service Unavailable`: `storage_unavailable`

Cloudflare may independently return `429 Too Many Requests` before a request
reaches the Worker.

Validation errors may include `details`. Other errors omit it. Internal errors must not expose stack traces, database statements, secrets, or Cloudflare configuration.

## HTTP Behavior

- Request and response bodies use `application/json; charset=utf-8`.
- Public `GET` responses include `Access-Control-Allow-Origin: *`.
- Authenticated endpoints reject unsupported browser preflight requests.
- All responses include defensive security headers.
- The latest-result endpoint may be cached for five seconds.
- History responses may be cached briefly, but pagination must remain consistent.
- API clients must retry `429`, `500`, and `503` responses with exponential backoff and jitter.
- API clients must not automatically retry validation, authentication, or event-conflict errors.

## D1 Data Model

The implementation uses:

- A `transmissions` table keyed by `event_id`.
- An index ordered by `started_at` and `event_id` for deterministic history pagination.
- A singleton `settings` row containing `retention_days` and its update timestamp.
- Integer epoch milliseconds internally for timestamps where useful.
- Server-generated `received_at` values.

Database migrations are versioned and committed to the repository.

## Compatibility Policy

- Additive response fields may be introduced without changing the API version.
- Existing fields cannot change meaning or type within `v1`.
- New required request fields require a new API version unless a safe default exists.
- Clients must ignore response fields they do not recognize.
